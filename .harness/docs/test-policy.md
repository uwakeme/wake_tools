# 测试策略

> ⚠️ Wake Tools **没有自动化测试**。本文件描述的是手动浏览器验证流程,这是项目当前唯一的"测试"。

## 测试前准备

1. 终端 A:`npx wrangler dev`,等服务起来
2. 终端 B:确认 dev server 在 `http://localhost:8787`
3. 用 playwright MCP 起一个浏览器:`mavis mcp call playwright browser_navigate '{"url": "http://localhost:8787"}'`
4. 浏览器窗口调成 1280×800 (桌面)和 375×667 (移动)两个尺寸分别跑

## 每个新工具的验收清单

### 1. 路由 & 搜索
- [ ] 在搜索框输入工具名(或中文名)能搜到
- [ ] 按 Enter 或点击进入,工具面板正确渲染
- [ ] URL hash 同步更新(如 `#/json-format`)
- [ ] 浏览器后退按钮能回到上一页(工具间切换)

### 2. 输入边界

每种情况都要跑一遍:

| 输入 | 期望 |
|---|---|
| 空串 | 不报错、不卡死,显示空状态或示例 |
| 正常输入 | 正确输出 |
| 超长串(10KB+) | 不卡顿、无错位 |
| 特殊字符:`<script>`、`&"'` | 正确转义,不执行 |
| CJK 字符 | 正确显示 |
| Emoji | 正确显示 |
| 零宽字符 | 不破坏布局 |
| 明显非法输入(格式错误) | 友好错误提示,不白屏 |

### 3. 交互
- [ ] "复制"按钮真的把结果复制到剪贴板,且 toast 提示
- [ ] "清空"按钮能清空输入和输出
- [ ] "切换示例"按钮(如果有)能换内容
- [ ] 任何按钮不会触发整页刷新

### 4. 主题
- [ ] 浅色主题下文字、背景对比度足够(目测 ≥ WCAG AA)
- [ ] 深色主题下同样
- [ ] 主题切换不闪烁,持久化到 localStorage(如果项目支持)

### 5. 键盘可达性
- [ ] `Tab` 能按视觉顺序遍历所有可交互元素
- [ ] 焦点环可见(不是 `outline: none` 不补的)
- [ ] `Enter` / `Space` 触发按钮
- [ ] 搜索框 `Esc` 清空
- [ ] 弹层(如果有)`Esc` 关闭
- [ ] 跳转链接(`#panel`)工作正常

### 6. 移动端 (375×667)
- [ ] sidebar 不挡主区(或能被菜单按钮收起)
- [ ] 输入框不溢出
- [ ] 按钮可点(≥44×44 px 触摸目标)
- [ ] 字体不小于 14px
- [ ] 滚动顺畅

## 回归 smoke(改动后必跑)

如果改了 `js/app.js`(路由/搜索/主题)或 `css/style.css`(全局样式),所有现有 30+ 工具都要快速跑一遍,确认没破坏。

工具列表见 `js/tools.js` 里的 `WT.tools.register` 调用。每个工具至少跑一遍 "正常输入 → 复制" 这一条。

## 截图与归档

测试通过的关键截图(尤其是新工具的核心功能)用 playwright MCP 截下来,随汇报一起给 orchestrator:

```
mavis mcp call playwright browser_take_screenshot '{"filename": "json-format.png"}'
```
